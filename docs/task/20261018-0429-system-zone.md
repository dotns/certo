# 20261018-0429-system-zone Manage the base domain as a system zone instead of config records

- **status**: closed
- **priority**: P1
- **owner**: claude/session-f6963de7
- **createdAt**: 2026-10-18 04:29

## Description

Make certo a general authoritative DNS server with the ACME challenge API on top: the
records of `general.domain` (today the static `general.records` lines) become a zone row
in the database owned by the server, edited through the same zone/record API as every
hosted zone (admin routes), and served by the challenge responder without a restart.
`general.records` turns into a one-time seed imported when the system zone is first
created, then ignored.

Acceptance: a fresh database gets the system zone with the apex NS and the seeded
records; an existing database (schema 3) upgrades and gets the same; `PUT/POST/DELETE
/admin/zones/<base>/records` change what the DNS server answers for the base domain within
one request; users cannot see or edit the system zone; DNSSEC and AXFR on it are refused;
challenge TXT behaviour (httpreq, acme-dns, own certificate) is unchanged; all Rust gates
and the e2e suite green.

## ActiveForm

Turning the base domain's static records into a database-managed system zone.
